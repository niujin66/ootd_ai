## 3｜根因：B 建议的「导出时关掉扩展」在 4.2.9 里没有对应开关

导出脚本是 `bpy.ops.export_scene.gltf(...)`（`build_t02.py` / `finalize_t02.py` / `final_top001.py`），没有传扩展相关参数。我在本机 Blender 4.2.9 做了两组最小实验：

**实验 A —— `export_original_specular` 开关管不管用**

构造 Principled 材质（Specular IOR Level 0.44、Sheen Weight 0.3），分别以 `False` / `True` 导出：

| `export_original_specular` | `extensionsUsed` |
|---|---|
| `False` | `KHR_materials_specular`, `KHR_materials_sheen` |
| `True` | `KHR_materials_specular`, `KHR_materials_sheen` |

**两个值都照样输出。** 该参数只改变 specular 数值的换算方式，不是"是否输出扩展"的开关；导出器也没有独立的 sheen 开关。

**实验 B —— 什么条件下才不输出**

| Specular IOR Level | Sheen Weight | 导出的扩展 |
|---|---|---|
| 0.5（默认） | 0.0（默认） | **无** |
| 0.44 | 0.0 | `KHR_materials_specular` |
| 0.5 | 0.3 | `KHR_materials_sheen` |
| 0.44 | 0.3 | 两个都有 |

结论：**只有把材质节点恢复默认值才不输出扩展**，而这会改动外观参数。原包里 top-001 的 `specularFactor = 0.44`、top-002 的 `specularFactor = 0.5` + `sheenRoughnessFactor = 0.45`，确实是材质被调过，不是纯冗余。

所以"在导出设置里关掉这两个扩展"这条建议，在 Blender 4.2.9 上无法通过勾选实现；可执行的两条路只有：① 改材质（动外观）；② 导出后剥离（不动外观）。

## 4｜为什么选剥离，而且**不能重导出 03b**

- **不动外观基准**：剥离只删 JSON 里的扩展声明，BIN chunk 原样保留，结果与内置素材逐字节一致。改材质或重导出会连带改变 specular/sheen 的渲染表现，反而偏离团队已验收的基准。
- **不能重导出已交付的 03b**：C 已用正式入口导入并登记 `content_digest = f0c05a0d8b86a8bf…`（由 manifest + 三份 GLB 哈希算出）。只要 GLB 有一个字节变化，digest 就变，C 的验收记录和队长 `docs/acceptance-record.md` 全部作废；同时也会和内置素材哈希失配。**03b 目录至今一个字节都没动。**
- **不依赖客户端兜底**：交付件本身不带扩展，任何客户端 / 工具拿到就能直接加载。PR #36 / #39 的 `GlbSanitizer` 保留作最后一道防线，但发布口径以资产侧干净文件为准 —— 这正是你担心的"其他客户端未必这么处理"，已经满足。

## 5｜长期规范：把「导出后门禁」固化，不靠人记

新增仓库工具 `server/tools/export_glb_guard.py`（纯标准库，无第三方依赖）：

```bash
# 交付前门禁：发现禁用扩展 exit 1
python server/tools/export_glb_guard.py check <包目录或若干 .glb>

# 剥离（与 T02-candidate-20261117/tools/strip_khr_extensions.py 算法一致）
python server/tools/export_glb_guard.py strip <源目录> <目标目录> [文件…]

# 与基准逐字节自证
python server/tools/export_glb_guard.py verify <glb> <基准glb>
```

Blender 建模脚本里把导出调用替换为封装函数，落盘即干净：

```python
import sys; sys.path.insert(0, r"<repo>/server/tools")
from export_glb_guard import export_clean_glb
export_clean_glb(filepath=out, use_selection=True, export_apply=True,
                 export_yup=True, export_format="GLB")
```

11-19 实测：

| 检查 | 结果 |
|---|---|
| `check T02-candidate-20261117` | 3/3 PASS，exit 0 |
| `check T02-candidate-20261113` | 拦下 2 个文件、报出 10 处扩展出处，exit 1 |
| `strip` 11-13 原包 → `verify` 对比 03b | 两件均 `IDENTICAL`（981,408 / 671,540，哈希一致） |

规范三条，建议写进 T02 导出流程：

1. 任何 GLB 交付前必过 `check`，**禁止把带 `KHR_materials_specular` / `KHR_materials_sheen` 的文件放进 handoff 包**；
2. 客户端兜底只作补偿层，不作为"资产可以不干净"的理由；
3. 一旦某版本已被 C 导入并登记 digest，**该目录冻结**，后续修复只出新版号、新目录，不覆盖。
