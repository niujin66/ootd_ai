## 一、判定规则（先说清，避免扯皮）

1. **不同哈希 ≠ 外观通过。** 本包哈希变了（剥离材质扩展），外观要通过必须重新判一次。
2. `top-001` 保留 11-12 历史通过范围（四条复核意见已通过）；本次只判**回归**：剥离扩展后有没有变样。
3. `top-002` **首次独立判定**，不继承 top-001 的结论。
4. 每项三态：**通过 / 不通过 / 未测**。看不清就写"未测"，不要写"通过"。
5. 已知遗留项（历史已交底）**不算不通过**，只登记：印花为照片级平面投影、背印在正侧方压到侧缝、腋下投影拉伸、领圈滚边偏硬。
6. **模拟器结论不回填本单。** 11/21 的 Q03-fit 只作背景；11/22 必须重新在真机逐件判一次。
7. **按文件哈希认包，不按目录标签。** `fixture-face-03` 这个标签下**至少出现过三套不同内容**：① APK 内置 `assets/local-demo`（与 03b 等价，981,408 / `45301ea0…`、671,540 / `8502d846…`）；② 11-13 带扩展交付包（981,688 / `64bca93f…`、672,096 / `ceda31dc…`）；③ **设备 filesDir 里的 11-18 早期远端版本**（981,412 / `503172eb…`、671,544 / `ad07321c…`，B #12 10:34 实测）。加上 `fixture-face-03b` 共四套。现场一律以 `45301ea0…` / `8502d846…` 两个哈希为准，记录同时写「目录标签 + 实际哈希」；**命中 981,412 / 671,544 就是没同步到 03b，先回去点「拉取目录」**。
