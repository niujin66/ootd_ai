## 0｜开工前第 0 步：`adb reverse` 与「同步真的生效」四判据

> 来源：@Journey668 11/21 11:40 #13「明天现场提醒」，#19 同文（给 C）。**今天上机第一件事就会撞这个。**

### 0.1 先查 reverse，再点「拉取目录」

点「拉取目录」若报 `远端同步失败：Failed to connect to /127.0.0.1:8000`，**不是服务端没起、也不是 App 地址配错**（`curl /v1/health` 是 200、`/v1/catalog` 正常返回 03b）。真因是 `adb reverse` 挂在 adb server 进程上，而那台机器的 adb server 每条命令都在重启（每次打印 `* daemon not running; starting now at tcp:5037`），server 一重开 reverse 就没了。

```bash
adb reverse --list                      # 判据：里面有 tcp:8000 才继续
adb reverse tcp:8000 tcp:8000           # 没有就重设
adb reverse --list                      # 再查一次，确认没被清掉
```

稳一点挂后台 watchdog（10 秒自检一次）：

```bash
while true; do
  adb reverse --list 2>/dev/null | grep -q "tcp:8000" || adb reverse tcp:8000 tcp:8000
  sleep 10
done
```

**两个别当判据的探活方式**：Android shell 不支持 `/dev/tcp`（`echo > /dev/tcp/127.0.0.1/8000` 报 `No such file or directory` 是 shell 没这功能，不是端口不通）；手机上没有 `wget`（`toybox: Unknown command wget`）。用它们判断端口会得到完全错误的结论。

## 四条别踩的坑

- **同步失败先查 reverse**：报 `Failed to connect to /127.0.0.1:8000` 不是代码 bug，先 `adb reverse --list`（第 0 步）。
- **模拟器 ≠ 真机**：11/21 的 Q03-fit「通过（肉眼级）」只作背景。
- **目录名 ≠ 内容**：`fixture-face-03` 标签下出现过三套内容（内置 / 11-13 带扩展包 / 11-18 设备早期版），按哈希认；命中 981,412 / 671,544 就是没同步到 03b。
- **哈希 ≠ 外观通过**：03b 导入成功、X01 离线恢复通过、后端回归通过都不等于四视角贴合通过；两件真机结论目前仍是「未测」。
