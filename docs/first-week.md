# 四人职责与首周验收

首周目标是在一名本人重建的三维人物上切换两件同类短袖，并在 Android 真机旋转查看。第 1 天从队员认领开始算。A、B、C 对应三位队员，认领后由成员 C 记录每项任务的负责人和下一次检查时间。

| 角色 | 负责的结果 | 交给谁 |
| --- | --- | --- |
| 队长 | 确定人物重建路线，跑通本人影像到三维人物，确认可交付手机端的资产格式。决定范围、架构和付费算力。 | 将人物模型和加载说明交给 B，运行记录交给 C |
| 成员 A | 准备可用于重建的本人影像，整理两件短袖，按确定的路线制作或整理可替换的衣物资产。 | 人物输入交给队长，衣物资产和编号清单交给 B |
| 成员 B | 负责 Android 端的加载、旋转、缩放和换装。第 2 周把推荐结果接到衣物切换。 | 可安装版本、安装步骤和真机记录交给 C |
| 成员 C | 负责日常协调、环境复现、独立验收和材料证据。整理阻塞项与测试结果，安排复测。 | 失败记录交给对应负责人，须拍板的问题集中交给队长 |

## 队长负责重建与关键决定

- 首先确定一个候选，核对代码和权重获取条件，验证官方样例，再使用 A 提供的本人影像。
- 核对重建人物的脸部和体形，和 B 一起确定可加载的资产格式。交付人物文件、操作步骤、输入编号、模型版本和耗时。若运行失败，交付最小复现步骤和报错。
- 需要队长决定的事项包括重建路线、资产接口变更、参赛范围和付费算力。C 汇总后提交决定项，队员同时推进各自能做的任务。

## 成员 A 负责采集和衣物

- 第 1 天先挑两件同类短袖，编号 `top-001`、`top-002`。分别拍清晰正背面，记录衣长、胸宽和袖长，注明测量单位。
- 找一名自愿参与者并记录使用同意。先准备完整头脚可见的正面、侧面全身照及正面脸部近照。穿普通合身衣物，光照均匀。按队长确认的模型要求补拍。
- 路线确定后按约定准备两件独立三维衣物。交给 B 时写清每件衣物的编号、对应文件和使用方式。照片与模型在团队内部交接，公开任务只登记样本编号。
- 队长核对人物输入能否用于重建。B 核对两件衣物能否按编号加载。若制作卡住，A 先交照片、尺寸和编号，和队长明确缺的工具或步骤。

## 成员 B 负责 Android 试衣

- 第 1 天先确认 Android 工具能启动、手机能连接。准备一个简单的试衣页面，包含查看模型和选择两件衣物的入口。
- 等本人模型期间，可以用有许可的测试网格检查加载、旋转、缩放与切换，记录为“测试资产”。拿到真实资产后，检查同一人物切换两件短袖，正面、侧面、背面各看一次。
- 交给 C 时提供对应版本、安装步骤、手机型号、操作步骤和实际结果。第 2 周接入推荐结果时，用衣物编号定位资产，并处理找不到衣物和加载失败。

## 成员 C 负责跟进与验收

- 第 1 天登记任务、负责人和检查时间，准备人物对应、两件衣物切换、真机旋转三条验收用例。协助队长复现模型环境，记录版本、耗时和报错。
- 每个工作日集中查看一次状态，记录当前可用结果、阻塞和下一步。一般问题直接找对应负责人，需要队长决定的事项汇总成一条，写清选项和影响。
- 收到可安装版本后独立复测。通过就记录版本和证据，失败就写复现步骤并退回负责人。测试资产可以通过加载测试，本人还原要另用本人影像验收。
- 队长忙时，C 可以协调任务顺序、安排复测和组织普通 PR 的审核。由具备仓库权限的同学完成合并。C 自己的改动请对应模块负责人复核。

## 检查时间

| 时间 | 看实际结果 |
| --- | --- |
| 第 1 至 3 天 | 队长交官方样例输出或失败日志。A 交人物输入和两件衣物清单。B 交手机连接及测试网格加载结果。C 交可复现的检查记录。 |
| 第 4 至 7 天 | 核对本人影像和重建人物。在同一人物上切换两件短袖，并在 Android 真机检查正、侧、背面。C 记录通过项、失败项和下一步。 |
| 第 2 周 | AI 返回已有且可展示的衣物编号。B 验证点击推荐能切换到对应衣物，C 验证无匹配和加载失败。 |

分支、任务状态、记录和素材存放统一按[开发与协作规范](team-standards.md)执行。
