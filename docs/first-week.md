# 首周开工任务卡

开发与交接先读[整体架构](architecture.md)。该文统一运行位置、资产版本和接口，各角色按下列任务执行。

三位队员认领 A、B、C。成员 C 把姓名、任务编号和下次检查时间记在任务表里。第 1 天从认领起算，队长没上线时三位队员也可以按下面的第一项开工。

| 谁 | 第 1 天只看这项 | 交给谁 |
| --- | --- | --- |
| A | A01，收齐两件短袖的正背照片、三处尺寸和编号 | C 检查清单，后续交 B 对接 |
| B | B01，在 Android 手机打开写着「衣序」的最小页面 | C 按提交里的步骤复现 |
| C | C01，建任务表和验收表，把今天的结果收齐 | 各负责人看自己的下一步，队长只看待决定项 |
| 队长 | T01，定一个人物重建候选，记录能否跑样例 | C 跟进复现，B 等人物资产 |

## 11 月 9 日后的执行顺序

Android 首页已合入，B 已记录真机启动通过，C 独立复测待确认。A01 的两件衣物素材已提交待验收。电脑端已用 PIXIE 官方样例导出并回读原姿势及 T 姿势 GLB。本人相似度、两件上衣贴合和手机三维换装仍待验证。

### 接下来 48 小时

| 人员 | 先做什么 | 交付及通过条件 |
| --- | --- | --- |
| B | 开始 B02，用团队自制或允许分发的测试人物和两件独立上衣，验证 Android 加载与交互 | 真机能拖动查看前、侧、后，在同一个人物上反复切换两件上衣。交运行说明、提交版本和操作记录 |
| A | 交 C 核对 A01，然后用同一基准姿势先做一件独立短袖。先调领口、肩线和下摆，再做第二件 | 交 `top-001.glb` 和模板来源，B 能将它与测试人物放在同一坐标系加载。通过后按同样流程制作 `top-002.glb` |
| C | 复核 A01 和 B01，再按 B 的版本复测 B02 | 分别记录素材、真机启动、三维旋转和衣物切换。每项记通过、失败或未测，以及下一步负责人 |
| 队长 | 记录 T01 的官方样例结果，和 A、B 对齐同一姿势、朝向、米制和资产编号。测试资产接口可先用样例数据 | 留下模型版本、导出文件格式、失败复现方式。确认两件上衣在同一人物上切换后再推进真实 AI 接入 |

B02 的测试资产用于验证加载和切换。正式的本人试衣仍按 Q03 使用参与者影像产生的人物和两件与其适配的衣物。PIXIE 的代码、权重与个人资产按许可及团队约定留在本地。

### 照片收到后

1. 用现有试跑流程先出本人原姿势和固定姿势 GLB。请本人核对脸部和体形，单独记录头发、纹理等未达到的效果。
2. A 用同一姿势的本人模型调整两件上衣。B 接入同一版本的三件资产，C 在真机检查两个方向的切换和正、侧、背面效果。
3. 11 月 14 日前检查 Q03。若相似度、贴合或加载卡住，分别记录原因与负责人。优先解决这三项，再增加界面或衣物类别。

第 2 周接入 AI 推荐。先用样例响应验证衣物编号确实驱动换装，再接真实模型，由 C 验证已有衣物、无匹配和错误编号三种情况。

## A 负责采集和两件上衣

**A01 第 1 天整理两件短袖。**

- [ ] 选两件版型相近的普通短袖，编号 `top-001`、`top-002`。
- [ ] 每件衣服平铺，拍完整正面和背面。各存为 `front.jpg` 和 `back.jpg`，分别放在 `local-data/garments/top-001/` 和 `local-data/garments/top-002/`。
- [ ] 用厘米记录衣长、腋下平铺胸宽、袖长。在 `local-data/garments/measurements.csv` 按下面的表头填两行。

```csv
garment_id,length_cm,chest_width_cm,sleeve_length_cm,front_file,back_file
```

**交付和验收。** 把本地清单交给 C。C 核对两行编号、四张照片和六个尺寸，公开任务只登记「A01 已核对 2 件」。照片和测量文件走团队内部渠道。

**A02 第 2 至 3 天采集一名参与者。** 本人同意后，准备清晰的正面全身、侧面全身、正面脸部近照，放进 `local-data/people/person-001/`。全身照露出头脚，光照均匀，穿普通合身衣物。把文件和采集条件交队长，队长根据模型要求确认是否补拍。

**A03 第 4 至 7 天交付衣物资产。** 第 3 天检查时，队长和 A 确认可用的短袖模板及制作步骤，队长和 B 确认导出格式和对齐方式。A 按该步骤做两份独立资产，套用各自实拍外观，按尺寸调整。交付 `top-001`、`top-002` 对应文件和清单，由 B 验证能否分别加载。遇到导出或对齐问题，A 保留已完成的文件并交具体卡点，队长负责判断该改导出还是改适配。在格式待定时先完成 A01、A02。

## B 负责 Android 试衣

**B01 第 1 天交一个能打开的 Android 页面。**

- [ ] 在自己的分支 `feat/android-starter` 工作。如果主分支尚无 Android 工程，用 Android Studio 建立一个 Kotlin 应用，放在仓库的 `android/`，首页显示「衣序」。
- [ ] 连接一台 Android 手机，在 Android Studio 选择设备并运行。确认手机能打开首页。缺手机时先在模拟器验证，真机状态记为「未测」。
- [ ] 提交工程和 `android/README.md`。README 写打开哪个目录、怎么运行、用的设备以及当前实际结果。交 C 的是提交链接和操作步骤。

**B02 第 2 至 3 天验证三维加载。** 先用有许可的三维测试资产验证手指拖动能看到正、侧、背面，并能在 `top-001`、`top-002` 两个测试选项间切换。等 A 的素材或队长的模型期间可以继续此项。按钮只切文字时，C 只验收界面切换。

**B03 第 4 至 7 天接入本人和衣物。** 用队长交付的人物和 A 的两件衣物替换测试资产，现场切换两次并旋转查看。记录原衣残留、穿模或加载失败，交 C 独立复测。模型迟到时交当前可运行版本和缺失的资产编号。

设备连接和运行参考 [Android 真机调试指南](https://developer.android.com/studio/run/device)。

## C 负责日常协调和复测

**C01 第 1 天登记任务和结果。**

- [ ] 建一张任务表，写入 A01、B01、C01、T01 的负责人、状态、交付物和下次检查时间。公开任务登记在仓库 Issues。验收所需的个人素材另在团队内部交接。
- [ ] 按下面的验收表建四条记录，先把结果填为「未测」。收到 A 的清单就核对素材数量，收到 B 的提交就按其 README 复现。
- [ ] 每天收一次结果。发给队长的内容只汇总需要决定的事项，每项写清问题、建议和影响。普通缺文件或复现问题直接找 A 或 B。

| 验收编号 | 检查动作 | 通过条件 | 时间 |
| --- | --- | --- | --- |
| Q01 | 打开 A 的清单和素材目录 | 两个编号各有正背照片、三个厘米尺寸 | 第 1 天 |
| Q02 | 按 B 的说明启动应用，再拖动测试模型和切换衣物 | 首页能打开，随后三维模型可旋转且两件衣物可分别加载。两步分别记录 | 第 1 至 3 天 |
| Q03 | 核对参与者影像和三维人物，再于真机依次切换两件上衣 | 本人确认脸部和体形能对应自己。人物保持一致，正侧背面可查看两件衣物，未发现影响演示的穿模或残留 | 第 4 至 7 天 |
| Q04 | 输入场合后点推荐结果，再测无可用衣物 | 结果引用已有衣物编号并加载对应衣物。无候选时给出提示 | 第 2 周 |

**复测怎么记。** 每条写任务编号、提交、设备、输入编号、复现步骤和结论。失败就保留报错或可公开的截图，退回对应负责人。缺素材或设备时登记「未测」和缺什么，约定下次检查。

## 队长负责本人重建和 AI 推荐

**T01 第 1 至 3 天只验证一个候选。** 选定候选，核对模型权重获取方式、使用条款、输入要求及导出格式。用官方样例跑一次，交命令、模型版本、输出或首个可复现报错给 C。C 可以先整理依赖和样例步骤，队长确认是否继续该候选。确因显存受限再评估付费算力。

**T02 第 4 至 7 天交本人的三维人物。** 用 A 的 `person-001` 影像运行，保存输入编号、模型输出、耗时和本人核对结果。和 A、B 用同一坐标、朝向、比例和固定姿势做一次加载检查，再把人物和导出说明交 B。

**T03 第 2 周接推荐。** 队长负责推荐逻辑和可运行入口，C 先写「有合适衣物」「没有可用衣物」「返回未知编号」三条用例，B 把推荐结果接到切换。输入用场合、偏好和可用衣物编号，输出用 `garment_id` 和 `reason`。无合适衣物时 `garment_id` 为 `null`，理由说明缺项。返回未知编号时保持当前衣物并提示加载失败。B 可用明确标记的样例响应先接页面，真实 AI 验收由 C 用实际运行的推荐结果复测。

## 资产交接

人物和衣物优先采用 GLB 分件导出，作为同一人物和固定姿势的整包交付。清单使用 `manifest.json`，保存在 `outputs/handoff/person-001/v1/`。字段、版本和手机接口按[整体架构](architecture.md)执行，发布前由 B 检查实际加载和对齐。

第 3 天检查样例输出、衣物清单和手机三维加载。第 7 天按 Q03 检查本人重建、两件衣物和真机。哪一步缺失就记录责任人、卡点和下一次检查时间，其他已具备输入的任务照常推进。
