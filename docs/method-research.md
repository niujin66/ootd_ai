# 写实人物与服装：方法调研及路线选择

调研日期：2026-11-11（北京时间）。项目依据为 `main@89eb768`、现有实验记录及 Issues #13、#15、#19。本文是工程路线与实验设计；没有新增高斯训练结果，也没有把论文展示效果记为项目实测。

## 1 当前选择

主线使用 **已确认的 B 版身体 + 可替换的头部外观 + 按实物制作的独立衣服 + Android 本地 GLB 渲染**。身体和 `pose-001` 固定，头部实验在离线阶段进行；验收后合并为新的 `person-001.glb`。手机仍使用一人物、两上衣的现有协议。

首件白色短袖先修版型，再做纹理。第二件是蓝色翻领 POLO，须有自己的领片和门襟，不能仅给短袖换蓝色贴图。推荐服务只选择已存在、已适配的衣物，不负责生成几何或证明尺码合身。

头部继续研究高斯转网格，优先验证相机覆盖。现有两次最大连通模型仅注册 23/96、28/96 帧，训练输入尚未通过；小重投影误差不能单独证明头部几何正确。保留现有身体作为比较基准，不因头部试验失败重做衣物。

## 2 方法比较

下表“适用性”是结合当前人力、素材、8 GB 级本机显存及已有代码的判断，不是论文排名。

| 方法 | 能提供什么 | 对本项目的限制 | 采用方式 |
| --- | --- | --- | --- |
| B 版身体 + 多视角纹理修整 | 已有体型、姿势、衣物坐标，修改范围可控 | 正面投影不能补全侧脸、头发与耳部几何 | 主线基准；先补最明显的头发轮廓、侧后颜色和颈部接缝 |
| COLMAP SfM + MVS + 网格 | 相机位姿、稠密表面，可继续清理和贴图 | 皮肤弱纹理、头发反光、人物运动都会增加难度；仍需要足够覆盖 | 相机通过后作为几何对照，不默认比高斯差。[COLMAP 教程](https://colmap.github.io/tutorial.html) |
| 原生 3DGS | 从多视角影像学习视角相关外观 | 高质量渲染不等于可换衣的三角网格；当前手机加载链路接收普通 GLB | 头部外观对照，不直接进入首版手机渲染器。[原始项目](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/) |
| 3DGS → SuGaR → 纹理网格 | 表面对齐、网格提取、联合优化，另有传统 UV 纹理导出 | 混合高斯表示与普通纹理网格效果不同；官方 README 仍列出 Windows 路径兼容待处理 | 已有环境能运行时优先复用；最终用普通 GLB 验收。[SuGaR 实现](https://github.com/Anttwo/SuGaR) |
| 2DGS → TSDF 网格 → 清理/烘焙 | 面向表面重建的高斯表示，官方提供网格提取路径 | 仍需有效相机、CUDA 环境和后续纹理处理，不能保证本人数据成功 | SuGaR 环境受阻时的后续候选，不在同一个两小时窗口同时搭两套环境。[论文项目](https://surfsplatting.github.io/)、[实现](https://github.com/hbb1/2d-gaussian-splatting) |
| 实物尺寸 + 衣片/模板 + 离线布料整理 + UV | 独立衣物、明确边界与真实印花，符合现有换衣架构 | 平铺尺寸不是穿着后的包围盒；模板仍需人工改领口、袖口、侧缝 | A 的主线，先轮廓后材质，冻结一个姿势的结果 |
| 单图生成整个人物/服装、2D 试穿 | 可做视觉参考或独立图片效果 | 对本项目而言，身份一致、背面细节、真实尺寸和人衣分离均需另验 | 本轮不接入；完整两衣演示通过后再评估 |

## 3 对 Gemini 建议的取舍

| 建议 | 本项目处理 |
| --- | --- |
| 参数化身体配服装模板 | 采纳制作思想，继续用已确认的 B 版；更换 MakeHuman/Daz 会要求重做身份、姿势和两衣适配 |
| 高模细节烘焙到低模 | 采纳。先保证轮廓，再将褶皱细节烘焙到切线空间法线贴图；法线不能修正错误下摆轮廓。[Blender 烘焙说明](https://docs.blender.org/manual/en/latest/render/cycles/baking.html?highlight=bake) |
| 布料解算 | 用于离线定型。A 先沿用现有 Blender 工程；只有版型已对齐而褶皱仍差时才增加模拟。Blender 有缝合弹簧机制；商业软件需要已有可用授权与熟练人员才值得引入。[Blender 缝合机制](https://docs.blender.org/manual/it/2.91/physics/cloth/settings/shape.html) |
| 同源人体和服装保证零穿模 | 不接受这种保证。共同坐标能减少配准问题；袖口、腋下、领口、布料余量和身体遮挡仍要逐面检查 |
| 身高/体重/三围直接驱动滑块 | 延后。不能由几个测量值保证恢复本人外观，也不能让现有衣服自动适配任意体型 |
| 用照片 Sobel 梯度生成真实法线/粗糙度 | 不作为物理重建依据。印花、光照和折痕都会产生图像边缘；本项目用实拍提取颜色/图案，用几何或已知材质产生细节 |
| Draco/KTX2 后必定无损、几 MB、60 FPS | 不作承诺。编码设置、解码能力、贴图显存与设备都影响结果；先保留当前兼容格式，再做单变量压缩对照。Draco 接入需要加载器支持对应扩展。[扩展规范](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_draco_mesh_compression/README.md) |
| 换 Unity/WebGL、叠加 2D 试穿与天气 Agent | 本轮保留 Kotlin/Compose/SceneView/FastAPI；新引擎和新产品流程会分散实衣与联调工作 |

以上推断基于本项目目标：可辨认的本人、两件真实衣服、可运行的推荐换装。提交材料应写清“离线辅助制作”和人工参与范围，不声称全自动、任意衣物或尺码预测。

## 4 头部实验：输入先合格，结果再比较

### 输入检查

1. C 先复核现有 96 帧与相机轨迹：哪些帧注册、各视角是否在同一个模型、特征点落在头部还是背景、正侧背是否有大段缺失。
2. 保持相同镜头/焦距和曝光；人物尽量静止，移动相机产生视差。若人物转动而背景静止，应单独处理运动前景，不能将背景的成功注册当作头部成功。裁剪、缩放或去畸变后须同步更新相机参数。
3. 若现有输入不合格，先列明确的缺视角及原因，再安排一次补拍；建议短时间完成一圈并补耳部、头顶，避免拖长拍摄引入表情和姿态变化。这是项目采集建议，帧数本身不是质量保证。

COLMAP 官方建议高重叠、稳定照明、不同相机位置和可匹配纹理；视频应适当抽帧。这里据此优先改善输入，不反复增加训练步数。[采集与重建指南](https://colmap.github.io/tutorial.html)

### 两小时可行性窗口（T04，先完成当日集成验收）

| 累计时间 | 做什么 | 必须留下的结果 |
| --- | --- | --- |
| 0–20 分钟 | 检查输入、相机轨迹、现有 GPU/编译环境 | 注册帧清单、视角覆盖图、首条有效环境报错或小样成功日志 |
| 20–50 分钟 | 最多一轮针对性相机修复；可复用已有结果 | 一个覆盖正/左/右/后的连通模型；不合格即停止训练并写补拍清单 |
| 50–80 分钟 | 环境已就绪时，运行一个低成本头部训练候选 | 方法与代码版本、输入哈希、参数、用时、显存峰值、保留视角渲染 |
| 80–110 分钟 | 能完成时导出普通网格、清理并准备 GLB | 网格与高斯各自的同角度截图；未完成的阶段明确写“未完成” |
| 110–120 分钟 | 与旧头部对照、总结是否继续 | 四视角对照、阻塞、下一次实验唯一变量；不以安装成功代替外观成功 |

时间限制是可行性检查预算，不承诺两小时产出高质量头部。建议预设的输入门槛为主连通模型注册率 ≥70%，且正/左/右/后均有足够重叠；这是团队试验阈值，非学术标准。即使达到比例，只要轨迹或头部点云明显错误也不进入训练。

本机查询为 RTX 5070 Laptop、8151 MiB 显存。原始 3DGS README 的论文质量训练参考是 24 GB，并给出小显存调整办法；8 GB 只作为缩小输入、限制增密的试验环境，不直接沿用论文预算。先测 CUDA 扩展与当前 GPU 的兼容性，再决定训练。环境与输出放在项目约定的本地目录，不为试验重装系统或清理无关磁盘。[官方硬件与小显存说明](https://github.com/graphdeco-inria/gaussian-splatting#hardware-requirements)

### 三种结果必须分开验收

| 对照 | 检查方式 | 继续条件 |
| --- | --- | --- |
| 旧头部 vs 原生高斯 | 同视角、相近大小；保留未参加优化的有效视角 | 脸部结构、耳部、头发轮廓改善；没有只在训练角度好看的明显问题 |
| 原生高斯 vs 普通纹理 GLB | 同角度观察；记录透明碎片、孔洞、纹理缝与侧后损失 | 普通 GLB 自身优于旧版；高斯截图不代替该项 |
| 新头部 + 固定身体 + 两衣 | 正、左右侧、背部与颈肩近景；手机实际加载 | 本人确认相似度，颈部接缝自然，身体配准保持；两衣重新检查通过 |

保存输入划分、截图、命令、方法版本与失败记录到 `outputs/experiments/head-<run_id>/`。不同方法使用同一输入和保留视角，拍摄/训练/人工清理耗时分开计时。只有一段视频的小样不能支撑广泛泛化结论。

## 5 实衣制作：修正 v1 的可执行步骤

依据 [C 对 top-001 的复核](https://github.com/niujin66/ootd_ai/issues/13#issuecomment-6791071735)，A 的 v2 按以下顺序做；不需要等头部实验。

1. **锁定基准。** 将同一 `person-001.glb` 作为只读参照，记录 SHA-256、姿势和源工程。所有视图保持相同相机、光照、比例。
2. **先做中性灰模。** 前后衣片、袖子与领口分别调整。修侧缝 A 字外扩、领口越肩/开洞、下摆包臀、袖口几何不一致这四项。体表外扩只可作起点，不能作为真实衣型的最终依据。
3. **解释尺寸。** 区分平铺宽、周长、穿着后包围盒和缝份。记录测量端点、单位、误差与参考图，先解决 53 cm 与 54.9 cm 的口径差异，不直接把 3D 包围盒缩到平铺宽。
4. **处理遮挡。** 先修衣服几何；确需裁去被遮挡的躯干面时，只裁两件衣服共同覆盖的交集，保留领口、袖口可见身体。基础身体文件不覆盖，另存导出版本；逐件检查穿孔和露肤。
5. **最后贴图。** 分前、后、袖、领 UV；印花不得镜像、拉长或跨缝。侧面使用连续布料色，去除实拍阴影造成的明显接缝；小褶皱才用法线。棉布先采用非金属、较高粗糙度，数值靠手机光照对照调节。
6. **统一源工程。** 灰模版和贴图版由同一几何导出，避免袖口再次分叉；POLO 可复用测量/UV流程，但领片、门襟与袖口独立制作。
7. **交完整证据。** `.blend`、独立 GLB、与人台叠加的四视角、衣物单独视图、尺寸说明、文件哈希；先由 C 复测，队长只确认外观取舍。

论文报告的指标、耗时和硬件只作背景；提交材料使用团队实测数据。具体系统边界见[架构](architecture.md)，执行顺序和可复现用例见[实施与验证清单](implementation-plan.md)。
