## 1 从当前代码到目标行为

| 编号 / 优先级 | 具体代码与当前行为 | 目标改动 | 验证条件 |
| --- | --- | --- | --- |
| R01 / P0 | [TryOnScreen.kt](../android/app/src/main/java/com/ootd/ai/ui/TryOnScreen.kt) 收到推荐后只按衣物 ID 查找；[CatalogModels.kt](../android/app/src/main/java/com/ootd/ai/data/CatalogModels.kt) 未保留响应 person_id | B 保存请求快照及操作序号，完整核对响应；手动换衣和换目录使旧请求失效 | 延迟旧请求，期间换衣/换包，旧结果不得覆盖当前画面 |
| R02 / P0 | 同页仅渲染 requested 对应的 garmentState；切换加载期间旧实例不在当前绘制分支；同步成功立即 active=新包 | B 区分当前与候选模型；候选 Ready 才提交画面 | 损坏 GLB/解码失败/快速连点时旧衣、人物和镜头始终保留；记录 20 次切换 |
| R03 / P0 | [RemotePackageRepository.kt](../android/app/src/main/java/com/ootd/ai/data/RemotePackageRepository.kt) 校验前依赖在线 health/catalog，cacheDir 只放 GLB；启动只读 APK 本地包 | B 持久保存目录与生效索引，提供无网络恢复入口；完整候选发布与画面发布分开 | 下载后强制停止应用、断网重启；仍可旋转与切两衣；无完整包时给清晰提示 |
| R04 / P0 | 同仓储删除 target 再 rename，失败后逐文件 copy；没有完成标记/生效指针；上层通用 runCatching 可能捕获取消 | B 不覆盖生效目录，元数据完整后原子更新索引；取消不提交；串行提交同人物版本 | 在下载、写元数据、提交索引处分别中断，重启恢复旧完整版本；同版本不同内容拒绝 |
| R05 / P1 | CatalogParser 跳过缺 ID/URL 条目，缺大小默认 -1、缺哈希可跳过校验；目录 ID 未做路径规则约束；CatalogApi 接受绝对 URL 并加令牌 | B 先严格验证整份目录，再进行任何文件写入；相对 URL/同源限制，重定向策略明确 | 缺哈希、错大小、重复 ID、空姿势、路径越界、跨域 URL 均在落盘前失败；人物 available=false 可正常加载 |
| R06 / P1 | 推荐解析宽松，未知 mode 在 UI 中被当作非 mock；[validate_model_output](../server/recommender.py) 用 get 读取 garment_id，缺键也可能成为 no_match | B 严格解析响应；C 要求模型字段显式存在、类型与状态一致 | 缺键、未知模式/状态、错类型、未知 ID 都报协议错误；明确 null + 合法 reason 才是 no_match |
| R07 / P1 | [asset_validation.py](../server/asset_validation.py) 汇总 scene.geometry 原始几何，未应用场景节点变换；未全面核对纹理/解码预算 | C 按节点实例与世界变换报告尺寸、统计材质和内嵌贴图；基础检查与人工检查分开 | 一个带平移/缩放节点的匿名 GLB 得到正确包围盒；坏纹理资源被识别；现有匿名包仍通过 |
| R08 / P1 | [db.py](../server/db.py) 自动取最近导入版本；[importer.py](../server/importer.py) 自动校验不包含人工外观结论 | C 先用独立候选库/资源根目录，验收后导入演示库；显式激活另做后续 PR | 导入未验收候选不改变正式演示的目录；验收记录绑定同一文件哈希 |
| R09 / P1 | TryOnScreen 同时处理网络、状态、渲染，磁盘模型实例未明确统一释放责任 | B 在 R01–R04 稳定后引入 ViewModel 与场景控制器，明确资源所有权 | 进出页面、前后台、连续换衣无崩溃；释放只发生一次；旧结果不回写新页面 |
| R10 / P1 | [CatalogApi.kt](../android/app/src/main/java/com/ootd/ai/data/CatalogApi.kt) 读超时 20s，后端模型默认也 20s；[recommender.py](../server/recommender.py) 配额检查与增加分开，分钟计数仅进程内 | C 先使服务端超时短于客户端，记录成功/失败耗时；正式并发调用前原子占用额度，规定单进程边界 | 可控慢响应下客户端收到明确 503；并发临界额度不超用；失败不暗转 AI 成功 |

P0 表示演示可靠性优先，不表示已真机触发。P1 分小 PR 完成；不要求为了表格覆盖率在 11/12 一次重写全部模块。每个 PR 写对应任务、测试范围与残留问题。
